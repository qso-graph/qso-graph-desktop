### Step 2 implementation and evidence

`settings-contract.ts` adds the checked `tabs` value to the existing settings
channel and per-user `settings.json`. `tab-session.ts` waits for the checked
catalogue, restores available destinations in order, and serializes subsequent
writes. Selection and drafts are not persisted. Restoration adds no page request.

`page-work.ts` is the page-owned draft interface, registered with `shell-store.ts`.
Its implementations are Callsigns' details and credential forms (`app.ts`),
Locations (`StationsPage.svelte`), guided setup (`SetupPage.svelte`), adapter
settings (`IntegrationsPage.svelte`), and Focus Area (`area-work.ts` and
`AreaCard.svelte`). Setup stays mounted after its first use; Focus Area's draft
belongs to the shell, so showing another page cannot destroy either draft.
Extension inputs are query fields with a **Show** action, not stored records;
`ExtensionPage.svelte` retains their drafts per page. Declared extension settings
and the application's ordinary settings save immediately.

`ConfirmDialog.svelte` has an optional third action and a gallery story, using the
gallery's existing light/dark themes. Dialog title IDs are unique. Tab focus waits
for the asynchronous close result. `app.ts` guards the real extension switch and
exports `mayCloseWindow()` for step 5, without wiring quit. A hidden page's data
request is cancelled and its late reply discarded (`QGD-HOM-0005`), so returning to it never
puts two requests out at once; page actions run on and keep their outcome (`QGD-APP-0021`).

The three new suites are registered in `scripts/suites.mjs`. The existing tab,
scheduler, settings and shell tests follow the changed contracts. The new tests
also exercise the actual page script handlers and compile/render the dialog.
They do not replace native focus or screen-reader acceptance.

Planted controls run locally, with each production-file mutation restored:

- Accept a malformed stored value; restore an unavailable destination; select a
  restored page at start; bypass catalogue readiness; write orders concurrently;
  request a restored page before it is shown.
- Omit showing the dirty tab; close on Cancel; name only one dirty tab; accept an
  unconfirmed save; close before save finishes; omit draft discard; bypass the
  actual extension-switch guard; bypass the window-close check; overlook an
  edit to a previously clean page while another page saves.
- Abort a request when its tab closes; replace a write's unknown result with
  cancellation; discard Locations, credential, Integrations, Focus Area or setup
  edits on a refused/failed save; remove the dialog's third choice.

All 23 mutations caused assertion failures, rather than import or compilation
failures. No planted mutation remains. Verification and sandbox limitations are
reported with the step's delivery; KI7MT acceptance remains pending.

### Step 3 implementation and evidence

`main/tab-menu.ts` supplies the native Tabs menu. Its actions go only to the
focused shell window, through the checked preload `onTab` subscription.
`renderer/tab-keyboard.ts` uses the existing store's order, MRU and asynchronous
close guard. Reordering leaves selection and MRU alone. Single-key menu
accelerators stay available while typing, including Close Tab; the renderer
does not listen for those keys again. The macOS chord stays outside text entry,
composition and modal dialogs, expires after 1.5 seconds, and resets on unrelated
input, menu commands and window blur. Its unprefixed arrow key keeps its normal
editing behavior.

`ui/tab-focus.ts` shares the tab bar's focus operation with keyboard commands.
It waits for rendering, focuses without scrolling the document, and reveals
the selected tab within the bar. A refused keyboard close leaves focus alone.
Tab and Shift+Tab are not intercepted; the header landmark and status-bar
controls keep their existing markup.
