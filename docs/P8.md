# P8 acceptance registration: Home and its cards

**Registered 2026-10-11**, before any of its code is written (`QGD-PRT-0003`). KI7MT re-planned P8
the same day: Home is the base product, and QG ADIF left the plan. The exit gate is
`QGD-PRT-0108`: on a new install Conditions and Your station are pinned and drawn by the core from
the extension's data; pins hold up to six, reorder and persist; only pinned cards fetch; a failing
source fails its own card and nothing else; screenshots approved by KI7MT in light and dark; it
runs on a Raspberry Pi 5. This document lists the tests that will show it. It is not a second copy
of the requirements, which stay in `QGD-SPEC-001` §4.6.

P8 depends on P7: On the Air is the first built-in extension, and it reaches the core only through
the extension API, as any extension does (`QGD-APP-0002`).

## What P8 has to satisfy

`QGD-HOM-0001`–`0010`, with `QGD-SEC-0006` and `QGD-SEC-0020` as they apply to card data and to
the Conditions fetch. On the Air is the first extension whose code runs, so P8 also builds the
extension host it runs in: `QGD-APP-0015`–`0023`, with `QGD-PRC-0004` (added 2026-10-11, when
KI7MT chose the VS Code model; reviewed twice by Codex before any code).

| Test | Required result |
|---|---|
| P8-contribution | A manifest's `cards` entries are read and checked when the extension loads: a missing name, description or refresh interval, or a duplicate id, refuses the manifest and names the field. The core's list of available cards is exactly the cards of the loaded, enabled extensions; nothing is listed that no extension offers (`QGD-HOM-0001`) |
| P8-shapes | Each card shape (figures, items, alert) renders from valid data. Data off the shape (an extra field, a wrong type, markup in a string) is refused and the card says it could not be shown; nothing from the extension reaches the page as markup (`QGD-HOM-0002`, `QGD-SEC-0006`) |
| P8-pins | Up to six cards pin; a seventh is refused with a reason. Order set in "Customize your pins" is kept in `settings.json` and survives a restart. Installing or enabling an extension adds its cards to the list and pins none of them (`QGD-HOM-0003`) |
| P8-day-one | A new profile starts with Conditions and Your station pinned, in that order (`QGD-HOM-0004`) |
| P8-fetch | An unpinned card makes no request. A pinned card makes none while another page is showing, and none sooner than its declared interval, measured with a clock the test controls (`QGD-HOM-0005`) |
| P8-failure | A Conditions source made to fail shows its own card's failure in words, while Your station and the rest of Home draw normally (`QGD-HOM-0006`) |
| P8-built-in | On the Air ships in the package and is enabled on a new profile. Turned off, its cards leave Home and the list; turned on, they are offered again. It holds only the grants its manifest declares, and the boundary gate shows it imports only `extension-api` and `ui` (`QGD-HOM-0007`, `QGD-APP-0002`) |
| P8-conditions | Against recorded NOAA SWPC responses shared with `solar-mcp`, Conditions shows the same solar flux, K and A indices, alert state and band outlook that `solar-mcp` reports for them. The fetch goes through the credential core to a host the source register names, and no other process connects (`QGD-HOM-0008`, `QGD-SEC-0020`) |
| P8-your-station | With a fixed clock and a test persona active, Your station shows UTC first, local time, and the callsign; with no persona it says so; with no network at all, it still draws (`QGD-HOM-0009`) |
| P8-screens | Screenshot baselines of Home with the day-one cards, and of "Customize your pins", approved by KI7MT in light and dark; axe clean |
| P8-pi5 | On a Raspberry Pi 5 with the day-one cards pinned: the window up and the cards drawn within ten seconds of a cold start, and the application's memory, measured across its processes, recorded against the floor (`QGD-HOM-0010`, `QGD-SCP-0009`) |
| P8-host | On the Air's code runs in the QG Extensions utility process and nowhere else: not in the renderer, not in main. The boundary gate and a check of the running processes both show it (`QGD-APP-0015`, `QGD-PRC-0004`) |
| P8-provenance | An extension shipped in the package loads. The same extension placed outside the package, with `"tier": "official"` in its manifest, is refused (`QGD-APP-0017`) |
| P8-identity | A request sent on one extension's channel naming another extension's identifier is attributed to the channel's extension, and cannot reach the other's data or grants (`QGD-APP-0018`) |
| P8-contract | A manifest with an unknown field, a missing `manifestVersion`, or an `engines.qgd` range the core does not satisfy is refused, naming the field or the version needed (`QGD-APP-0019`) |
| P8-lifecycle | Two cards needing the same extension at once activate it once. A failing `activate` marks it failed and its cards say so, with no retry until it is re-enabled. Disable deactivates it; re-enable activates it again. An overrun `deactivate` restarts the host and reports every extension it affected (`QGD-APP-0020`) |
| P8-messages | A request past its deadline ends unknown and a late reply to it is discarded; a duplicate reply is discarded; a cancelled request ends cancelled only when the extension confirms it; a message over the size limit, or one over the in-flight limit, is refused. The limits are read from `data/extension-limits.json` (`QGD-APP-0021`) |
| P8-supervision | A host made to hang is stopped by the watchdog and restarted; one made to crash repeatedly stops at the restart budget; requests in flight end as `QGD-APP-0021` says; replies from the replaced host are discarded; the screen names the affected extensions (`QGD-APP-0022`, `QGD-APP-0013`) |
| P8-window | The window is ready while the host has not started, and with nothing pinned no extension activates (`QGD-APP-0023`) |

### The Raspberry Pi 5

The arm64 `.deb` from CI, installed on a Raspberry Pi 5 with 16 GB and Raspberry Pi OS (64-bit),
booting from its SD card, under Xvfb. The page cache was dropped before every start, so each one is
a cold start.

| Start | Window and both cards drawn | Memory, summed across the application's processes |
|---|---|---|
| First, new profile | 8.6 s | 568 MB |
| Restart | 6.1 to 6.7 s | 555 MB |

Both are inside the ten seconds P8-pi5 sets. About 3.7 s of each is Electron loading itself from the
SD card, before any of this product's code runs. Nothing is fetched at start but NOAA's three feeds
for Conditions (`QGD-REF-0017`). From Settings, both reference resources were then downloaded on
the Pi, ADIF's definitions over TLS 1.2 (`QGD-SEC-0020`), and each built into `reference.sqlite`
without fetching the other.

**On memory:** `QGD-SCP-0009`'s floor is a Pi 5 with **4 GB**. The board measured has 16 GB. The
application used about 570 MB of it, which a 4 GB board holds with room to spare; the measurement
itself was not taken on 4 GB.

### Open

1. **P8-supervision: the screen does not name the affected extensions.** The supervisor records
   which extensions a stopped host affected and logs them, and each affected card says "The
   extension host stopped." No surface lists the affected extensions together, which is what the
   registration asks. To be written: Home says which extensions stopped, from the supervisor's
   status.
2. **`connection-capture` has not run on macOS since `716cffa`.** It saves a test credential, so
   it runs in a logged-in desktop session; CI does not run it. The guard that stopped it before its
   `QGD-SEC-0020` assertions is fixed (`bc1649a`). It needs one run on a Mac.

Two follow-ups, already agreed and tracked in `#37`: the reference-data buttons say Download and
Update, and ADIF offers Update only when a release pins a newer ADIF version.
