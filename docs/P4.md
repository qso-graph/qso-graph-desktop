# P4 acceptance registration — the engine

Registered before any P4 code is written, per `QGD-PRT-0003`. The exit gate is
`QGD-PRT-0104`: the engine starts on a free port, restore works, migrations
apply. This document lists the tests that will show it; it is not a second copy
of the requirements, which stay in `QGD-SPEC-001`.

P4 depends on P2, not P3. It does not wait on P3's screenshot baselines.

## What P4 has to satisfy

`QGD-ENG-0001`–`QGD-ENG-0013`, and `QGD-LOG-0011` (the engine's log held inside
the same caps as every other log). `QGD-ENG-0003` is already met and tested —
settings live in a file so the application starts before the engine is up — and
must stay met: nothing in P4 may make the shell wait for the database.

| Test | Required result |
|---|---|
| P4-binaries | The engine starts only from the pinned build recorded in `data/postgres-build.json`, verified by SHA-256 before use. A build whose hash does not match is refused, and the machine's own PostgreSQL is never reachable from the supervisor (`QGD-ENG-0004`) |
| P4-no-client-tools | The bundled build is asserted to contain the server, `initdb` and `pg_ctl` and no `pg_dump`, `pg_restore` or `psql`, so no code is written against a tool that is not there (`QGD-ENG-0005`) |
| P4-first-run | `initdb` creates the data directory on first run; a creation made to fail leaves no data directory behind, and the next start treats it as a first run rather than as a database (`QGD-ENG-0007`) |
| P4-lifecycle | Start, status and stop, driven by the supervisor; a start that fails reports why and leaves nothing running (`QGD-ENG-0006`) |
| P4-single-copy | A second start against a data directory already in use is refused, and the engine that was running is untouched (`QGD-ENG-0008`) |
| P4-endpoint | On macOS the engine listens on a Unix socket inside the application's directory and opens no TCP port — asserted against the running process, not inferred. The free-port chooser, which is the Windows path, is tested directly (`QGD-ENG-0009`) |
| P4-roles | One role and one schema per application; the password is fresh at each start and appears in no file on disk (`QGD-ENG-0010`) |
| P4-backup | A backup taken with the engine stopped records its major version, and the database it came from is readable again after a restore from it (`QGD-ENG-0011`) |
| P4-restore-refuses | A backup labelled with a different major version is refused rather than written over a live database, and a restore made to fail leaves the existing database working (`QGD-ENG-0012`) |
| P4-migrations | Drizzle migrations apply at start, the applied set is recorded, and a migration made to fail stops the engine rather than leaving it half-migrated (`QGD-ENG-0013`) |
| P4-engine-log | The engine's output is carried into the one log stream and held inside the same size, total and retention caps (`QGD-LOG-0011`) |
| P4-shell-starts-without-it | The shell starts, draws and reaches Settings with the engine stopped or broken (`QGD-ENG-0003`) |
| P4-no-regression | `make verify` stays green end to end, including the twenty suites that exist before P4 starts |

## Two things found before writing any code

**The bundled build has no client tools.** The only PostgreSQL build published
for macOS arm64 is Zonky's, on Maven Central; EDB publishes x86-64 only. It
carries `postgres`, `initdb` and `pg_ctl` and nothing else — no `pg_dump`, no
`pg_restore`, no `psql`. So backup is a copy of the stopped data directory
rather than a dump. That is exact and needs no tool we do not have; the cost is
that a backup is not portable across major versions, which `QGD-ENG-0011` meets
by refusing a restore from a different major rather than pretending.

**The exit gate says "a free port"; macOS will not use one.** A Unix socket
inside the application's own directory is strictly stronger — nothing on the
machine can reach the database, because there is no listener to reach. The
free-port chooser is still built and tested, because it is the Windows path and
`QGD-SCP-0004` keeps Windows a Release 1 target. `QGD-ENG-0009` records both.
If KI7MT wants the exit gate's wording to match, that is his call; the stronger
behaviour ships either way.

## Deliberately not in P4

- Reference data, personas as an application, and the app API: P5, P6 and P7.
- `pg_upgrade` and major-version migration, which is a migration release of its
  own and not a Part.
- A second operating system and a CI matrix, deferred by `QGD-SCP-0003` and
  `QGD-SCP-0004`.

## Approach

The binary set first, because everything else runs on it and because what it
contains decided two requirements. Then the supervisor's lifecycle, then the
endpoint, then roles, then migrations, then backup and restore. Each step keeps
`make verify` green rather than ending with one large reconciliation.
