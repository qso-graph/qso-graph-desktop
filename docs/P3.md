# P3 acceptance registration — the shell

Registered before any P3 code is written, per `QGD-PRT-0003`. The exit gate is
`QGD-PRT-0103`: e2e navigation, screenshot baselines approved by KI7MT in both
light and dark, and axe clean. This document lists the tests that will show it;
it is not a second copy of the requirements, which stay in `QGD-SPEC-001`.

## What P3 has to satisfy

Its own gate, plus requirements that already exist and whose surface lands here:
`QGD-FRM-0001`–`QGD-FRM-0005` (themes and the framework), `QGD-LOG-0013` (the
Logs page), `QGD-SEC-0008` and `QGD-SEC-0011` (the content policy and `{@html}`),
`QGD-CRD-0006` and `QGD-CRD-0007` (no secret and no connection in the renderer),
and `QGD-PRC-0006` (the renderer's hardening), none of which may weaken because
a framework arrived.

| Test | Required result |
|---|---|
| P3-navigation | The rail moves between pages, the current page is indicated, and the browser's history is not involved — there is no navigation away from the one bundled page (`QGD-PRC-0006`) |
| P3-keyboard | Every rail item and control is reachable and operable from the keyboard, with a visible focus indicator |
| P3-theme-system | With no stored choice, the shell matches the operating system, and changes with it while running, without a restart (`QGD-FRM-0001`) |
| P3-theme-override | Settings offers System, Light and Dark; System is the default; the choice survives a restart and applies immediately (`QGD-FRM-0002`) |
| P3-theme-contrast | Text and interactive controls meet the contrast the axe run requires, in both themes, measured rather than judged (`QGD-FRM-0003`) |
| P3-status-bar | The active persona is visible on every page, and stays correct across navigation and across a persona change |
| P3-personas-intact | The Persona workflow signed off at P1 — create, select, save, status, remove — still passes unchanged inside the shell |
| P3-logs-page | Settings carries the Logs page: the level switch writes the level the running process then uses, and Export diagnostics produces the archive `QGD-LOG-0012` already builds (`QGD-LOG-0013`) |
| P3-axe | No accessibility violation on any page, in both themes |
| P3-screenshots | A baseline per page per theme, captured for KI7MT's approval. Approval is his; the test's job is to produce them and to fail when one changes unexpectedly |
| P3-renderer-unchanged | After the framework lands: no credential in the renderer, no socket in the renderer, the content policy still forbids inline and remote scripts, and `{@html}` appears nowhere (`QGD-SEC-0008`, `QGD-SEC-0011`, `QGD-CRD-0007`) |
| P3-no-regression | `make verify` stays green end to end, including the fifteen suites that exist before P3 starts |

## Deliberately not in P3

- A low-light or red night theme (`QGD-FRM-0004`).
- Anything belonging to a later Part: the engine, reference data, personas as an
  application, the app API. The shell makes room for them and does not implement
  them.
- Signing, a second operating system, and a CI matrix, which `QGD-SCP-0003` and
  `QGD-SCP-0004` defer until Release 1.

## Approach

Svelte arrives (`QGD-FRM-0005`), which is the first framework in the renderer.
The order is: the build first with the hardening unchanged and the existing
Persona screen still passing, then the shell around it, then Settings and the
Logs page, then the themes, then the baselines. Each step keeps `make verify`
green rather than ending with one large reconciliation.
