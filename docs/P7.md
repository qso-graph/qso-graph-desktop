# P7 acceptance registration — the app runtime and the app API

Registered per `QGD-PRT-0003`. The exit gate is `QGD-PRT-0107`: **an application
without a grant is refused**, proven by a no-credential application (solar) and
a granted one (QRZ lookup), and by a test application that uses the API and
nothing else.

P7 depends on P6, which KI7MT signed off on 2026-10-09 along with P5. It has
two stages and the first is done: **the repository restructure**, then **the app
API itself**.

## What P7 has to satisfy

`QGD-REP-0001`–`QGD-REP-0006` for the layout, and `QGD-APP-0001`–`QGD-APP-0014`
for the runtime — a new area, written at the start of this Part because there
was none. It is constrained before any code by three decisions already taken:

| Decision | What it fixes |
|---|---|
| D-2 (KI7MT, 2026-10-05) | Three tiers — official, contributed, unofficial — with contributed and unofficial **sandboxed**: *"we want contributors, but don't want them breaking the box"*. The sandbox's design is named there as this Part's work |
| D-21 (KI7MT, 2026-10-07) | The frame holds only what every application needs and what protects the user. **Everything a ham does is an application** |
| D-33 (KI7MT, 2026-10-07) | **One API path.** QSO Graph's own applications use the same message API as every other application; no private shortcut, unless a measurement later shows one is needed and it is written down as a numbered decision |

## Stage 1 — the restructure, done

`QGD-REP-0002` held this until `QGD-PRT-0107` and not before, so it happened
here and not earlier. 78 paths moved, the compiled tree now mirrors the source
tree, and all 31 suites pass including the packaged launch — which is the one
that proves a shipped application still finds its own processes.

| Was | Is |
|---|---|
| `native/persona-core` | `packages/persona-core` |
| `src/main.ts`, the three brokers, settings, policy, diagnostics, attribution | `packages/main` |
| `src/preload.cts` | `packages/preload` |
| `src/logger.ts`, `src/logging.ts` | `packages/logging` |
| `src/persona-service.ts` and the persona and service contracts | `packages/personas` |
| `src/engine/*`, `src/engine-service.ts`, `src/engine-contract.ts` | `packages/engine` |
| `src/engine/reference/*` | `packages/reference` |
| `src/renderer/*` | `packages/renderer` |
| `src/renderer/ui/*` | `packages/ui` |
| `.storybook` | `storybook` |
| — | `packages/app-api`, `apps/` — both empty, both with a README saying what lands there and when |

**Cross-package imports are relative, not aliased.** `@qg/ui/…` reads better
and was written first, but `tsc` does not rewrite a path alias on the way out
and the main process has no bundler, so every one of them would have reached
Node unresolved. `dist/<package>/` mirrors `packages/<package>/`, so a relative
import that compiles also resolves at runtime.

**A tenth package, `logging`, was added to `QGD-REP-0001`.** The nine names in
it had no home for the logger that `main`, `engine` and `personas` all use:
putting it in `main` would have made the engine depend on the main process to
write a log line. The reason is recorded beside the requirement.

### What the restructure found

Three couplings that no one had decided, each invisible while everything lived
in one tree:

- **The logger reached into the engine** to sweep its own log directory —
  `isEngineLog` lived in the engine's endpoint module. The naming of a log file
  is logging's business (`QGD-LOG-0011`), so it moved.
- **A component reached into the frame's settings contract** for the words
  System, Light and Dark. Those are words on a control, so they are `ui`'s now
  (`packages/ui/theme-choice.ts`) and the settings contract imports them —
  which leaves `ui` depending on nothing, as `QGD-REP-0004` wants.
- **A story reached into the shell's page list.** That one stayed, waived and
  named: a `.stories.svelte` ships nowhere (`QGD-FRM-0009`) and the gallery is
  required to show a component the way the shell does (`QGD-FRM-0006`), so the
  rail's story reading the real page list is the requirement rather than a
  shortcut.

`QGD-REP-0006` and `scripts/package-boundaries.mjs` exist so the next one
cannot land quietly. The direction is checked over the imports as written, the
scope is walked rather than listed, and `tests/package-boundaries.test.mjs`
proves each refusal by building a tree that should fail. A wrong-direction
import was also put into a real component and both the gate and its test
failed on it.

### And a fourth gate that had gone quiet

`scripts/svelte-check.mjs` walked `src/`. After the move it found no components,
printed *"no components yet; nothing to check"*, and exited 0 — so the build
passed with nothing type-checked inside any component. That branch was true on
the first day of the project and a hole from the moment a component existed.
Finding no components is now a failure.

This is the fourth gate here to go quiet because of where it looked, after
ESLint reviewing no Svelte, svelte-check excluding every story, and the network
scan's scope (`QGD-SEC-0021`). Two more were caught in the same hour by failing
rather than passing: `scripts/storybook.mjs` and the icons tree walk.

registered tests below are what they assert.

**Signed off by KI7MT on 2026-10-10** at `39481ac`, recorded in

### What landed

| | |

### What the gate actually showed

`scripts/app-proofs.mjs`, 11 checks in the real application:

- the harness, declaring nothing, reads its own standing and is **refused every
  other capability**, each refusal naming the application and the grant;
- a source nobody registered is reported as **absent**, not as something to go
  and allow;
- solar, declaring one grant and holding no credential, **fetched through the
  core and drew its table**;
- qrz-lookup was **refused** the persona list on a fresh profile, **worked**
  once the grants were allowed, and was **refused again the instant
  `service:qrz` was withdrawn — with no restart**;
- the withdrawal took only what it named: `persona:list` kept working;
- the run left nothing in the real Keychain service.

`scripts/proofs-not-shipped.mjs`, 6 checks on the packaged artifact: no proofs
path among its 2,728 entries, no proof marker in the 79 kB renderer bundle, no
Apps entry in the packaged rail — and a control that the bundle does contain the
shell's own words, so an absent marker means absent rather than an empty file.
Proven to fail: packaging with `QG_DESKTOP_PROOFS=1` makes it report all six
markers.

### Open, and older than P7: a reference fetch blocks the persona service

Found by the exit gate failing about two runs in seven, and worth writing down
rather than leaving in a suite's comment.

`core.fetchReference` is a **synchronous** napi call, and the persona service
is one thread. So while a fetch is in flight — up to the core's 120-second
timeout — that service answers nothing else: a persona command issued behind it
comes back with nothing said. In the gate this showed as a persona that was
never created, with an empty message and the first-run offer still on screen,
and on the runs where it happened the evidence says NOAA had not answered.

The correlation is as far as the evidence goes; the mechanism above is read off
the code rather than proven by instrumentation. It is **not** a P7 defect —
the engine has fetched reference data through the same service since P5, and
`source.fetch` only gave an application a way to trigger it on demand. P7's
gate no longer depends on the ordering, so the coupling is out of the suite
rather than waited out.

Worth a look before an application that fetches often exists. Two shapes
suggest themselves: a fetch that does not hold the service's thread, or a
separate utility process for outbound fetches — the second being closer to
what `QGD-PRC-0004` already does for the engine.

### Two things worth keeping from the build

**`QGD-APP-0003` paid for itself immediately.** "The API is messages, not
functions" sounded like a design preference until the first call from a
component's own state failed with *"An object could not be cloned"*: Svelte
holds state in a `Proxy`, and a `Proxy` cannot be structure-cloned over IPC. The
same request written as a literal worked, which is a difference no application
author should have to know about. `bridge.ts` now rebuilds each request field by
field, per kind — so what crosses is a value, and nothing an application
happened to attach rides along.

**The baselines did not move.** The Apps page exists in `PAGES` but
`visiblePages()` filters it out unless `PROOFS_ENABLED`, so a release's rail is
unchanged and nothing needed re-approving. That was the deciding constraint on
how the proofs are kept out of the bundle: `packages/main/policy.ts` serves
exactly three resources over `qg:` (`QGD-SEC-0008`), so loading a page from disk
would have meant widening that to a pattern. Dynamic loading is what a
contributed application needs, and it arrives with the sandbox.

### Two constraints KI7MT set before the lookup is written

Both arrived through Bob on 2026-10-09, and both change what the Part has to
prove rather than how it is built.

**A lookup may be shown in full; it is not kept.** My first draft of this had
the core strip street address, email and telephone before anything crossed the
API, so they could never be displayed. KI7MT corrected it: showing the operator
what QRZ returns for a lookup they asked for is **QRZ being the source**, the
same as reading it on QRZ's own site. The never-a-PII-source rule is about what
this product keeps and passes on.

So the line is **storage and egress, not the screen**: no log, no database row,
no cache, no file, nothing in an export or a sync. What may be persisted is a
named allowlist of radio fields, never *everything except* a list of
exclusions, because a denylist is a guess about somebody else's response format
and the format can change underneath it.

Written as `QGD-PII-0007`, with the personal-data rules rather than the persona
ones, because a lookup result is a **third party's** details — the one place
this product handles data belonging to someone who is not the operator.

Worth recording that the allowlist was right and its **boundary** was wrong. I
had reached for it one layer too early, which is its own kind of error: a
control in the wrong place looks like rigour and costs a feature.

**"Not shipped" is enforced, not intended.** The two demonstrations and the
harness must be absent from the packaged application, asserted on the built
artifact the way `QGD-FRM-0009` already proves the gallery is absent. A
demonstration that reached an operator would be a feature nobody wrote.
`QGD-APP-0014.1`.

### What is settled before writing it

- **The enforcement point already exists.** As first written, `QGD-CRD-0002`
  put the grant model's enforcement in the credential core, and `QGD-ENG-0010`
  gave one role and one schema per application. On 2026-10-10 KI7MT named the
  app broker as the enforcement point, and `QGD-ENG-0010` was retired with the
  PostgreSQL engine (`QGD-HDBK-001` §13). The grant model is not being
  invented from nothing; it is being connected to two places that were built
  expecting it.
- **The transport is the existing one.** `main` is the IPC broker
  (`QGD-PRC-0003`) and three brokers already run on a typed, validated
  contract. The app API is a fourth of the same shape, which is why
  `QGD-APP-0003` costs nothing to satisfy now and would cost everything later.
- **Only the official tier loads.** The sandbox contributed and unofficial need
  is a later Part, so until it exists a manifest whose tier is not `official`
  **fails to load** rather than loading with the frame's privileges
  (`QGD-APP-0004`). Failing closed is the decision; the alternative ships a
  release that runs third-party code unsandboxed.

## Open observations

### A persona create that the service did not answer (1 run in ~10)

Seen once while hardening the exit gate, on 2026-10-09. The gate's own log
carried the shape of it: the persona service was answering `list` (the
precondition polled for exactly that and passed), the create was clicked with
both fields asserted to hold their values, and 15s later there was no persona
and `#message` was empty.

An empty `#message` with no persona is what a create the service never
answered looks like from the screen. The broker holds such a request for 30s
before answering in words, so the gate — which gave up at 15s — could not have
shown those words whatever they were. That mismatch is fixed (the gate now
waits 35s, past the broker's 30s) and the diagnostic now captures
`#page-title`, the element the assertion is actually about; the earlier version
dumped `h2` only, so a create that did nothing could not be told apart from one
that produced the wrong callsign.

**Not explained.** What it is not: the solar fetch (that proof fetches only
when asked, so it was never running at this point), and not the service
starting late (the precondition rules that out).

Seen twice in total, both times at this step, in something over thirty runs.
It belongs to the same open symptom as the `setup-walk` callsign flake — a
field's value or a reply being wrong or absent at the moment it is used — and
the instrumentation is what will name it rather than any reasoning from here.

The diagnostic is proven, not assumed: pointed at a heading that cannot exist,
it reports `#page-title was: "W1AW"` and `#message was: Persona saved.` from a
healthy run. That matters because the first version of it interpolated
`pageTitle` without declaring it, so the one failure it would have explained
would have become a `ReferenceError` instead, discarding the assertion, the
screen and the logs together. Found in review.

Next time it happens the two cases are now distinguishable: `#page-title` still
reading "Create a persona" means the create did nothing, and `#page-title`
reading a callsign that is not `W1AW` means the value was mutated — which is
the `setup-walk` flake, caught here. 12/12 after these changes, which is not
evidence it is gone.
